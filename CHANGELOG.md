## PARALLEL TRACK (continued) — `combined_splitter.py`: indentation repair + recursive dictionary-verified fallback for multi-member compounds (धनधान्योपपन्नानि), 2026-09-30

- Opened by the user reporting that `combined_splitter.py` failed on a wrong indentation and asking for a sample run on `dhanadhānyopapannāni` (`--scheme iast`).
- **Indentation**: in an earlier upload, `def split_word(self, deva_word):` inside `class CombinedSplitter` sat at column 0 with a tab before its docstring (`IndentationError`, line ~717). Re-indented to 4 spaces. The copy in `03\samasa` at the time of the later run already parsed cleanly.
- **The user's own run then showed no crash but no split**: `[sandhi] [???] धनधान्योपपन्नानि`. Reproduced in a sandbox that had the real `sandhi_splitter.py`, `samasa_splitter.py`, `apte_dictionary.sqlite` etc. Root causes, all in the dictionary-verification step of `_best_samasa_decomposition`: (1) `apte_dictionary.sqlite` stores neuter a-stems with final anusvāra and masculine with visarga, so `धान्य` is present only as `धान्यं`, and the strict `dictionary_lookup` rejected it; (2) `उपपन्नानि` was rejected because `-āni` is not in `_stem_after_common_inflection`'s ending table; (3) the correct binary cut `धनधान्य | उपपन्नानि` therefore stayed `phonology-only` and was discarded, and a 3-member result was unreachable anyway because `धनधान्य` is itself a compound, not a headword.
- **Fix (new methods on `CombinedSplitter`, called only when the strict path returns nothing)**: `_member_lexical_forms` (bare / +ं / +ः, and `-ānि` stripped), `_member_in_dictionary` (≥4 sounds, never a bare consonant-final scrap), `_recursive_members` (depth ≤ 3; candidate cuts = plain akshara-boundary cuts plus `samasa_splitter` sandhi-aware binary candidates; prefers fewest atoms, then longest shortest-atom, then shortest total length so that a-restoration wins over long-ā when a+u and ā+u give the same fused vowel), `_recursive_samasa_fallback`. `_best_samasa_decomposition` now returns this fallback instead of `None`.
- **Result**: `धनधान्योपपन्नानि` → `धन + धान्य + उपपन्नानि`, all three atoms dictionary-verified (tagged `samasa`). Samāsa *type* is not determined by the fallback (label: "members dictionary-verified; type not determined").
- **Checked**: 29-word old-vs-new comparison (incl. false-positive traps नारदम्, साम्प्रतम्, विद्वान्, गुणवान्, मुनिपुङ्गवम्, चारित्रेण, सत्यवाक्यः) — 0 words changed. **Not run**: `--test` (corpus file `corpus_64word_ramayana_1.1.1-5.txt` was not available in the verification environment), `_self_check()`, and `sarga_analyser.py --gold`; the verification environment also had no `morphology\pada_analyser.py`, so the `samasa_classifier` path was off (`_pa()` returns False). These gates must be run on the project machine before the change is trusted.
- Delivered as a downloadable `combined_splitter.py`; **must be copied over `03_Sandhi_and_Samasa_Tools\samasa\combined_splitter.py`** (keep the existing `combined_splitter-BACKUP.py`). No other file was edited. Does not touch `sanskrit_grammar_engine.py`.
